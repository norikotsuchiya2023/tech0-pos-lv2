# 簡易POSアプリ（ベーカリー業態）要件定義書（Lv2）

対象業態：ベーカリー（町のパン屋、1〜2店舗規模、レジ1〜2台）

## 生成AI利用について

Claude（Anthropic）との対話により、業務要件の具体化・曖昧点の洗い出し・文章整理を行った。要件の採否・数値の決定（パスワード桁数、ロックアウト時間、MFA方式等）は人間が行った。

---

## 0. 前提条件

- Webアプリ（ブラウザ動作）
- フロントエンド：Next.js
- バックエンド：FastAPI
- インフラ：Microsoft Azure（DB：Azure Database for MySQL Flexible Server）
- カメラ付きデバイスでバーコードを読み取れること
- 個人情報は業務目的（店頭会計・値引き適用・売上記録）に必要な項目のみ取得・保持する（データ最小化）

---

## 1. 業務要件

### 1.1 アクター

| アクター | 役割 |
|---|---|
| レジ担当者 | ログイン（ID・パスワード＋MFA）してレジ業務を行う |
| 店舗管理者 | 商品マスタ・値引き・消費税率を管理する（本アプリのスコープ外。マスタは書き換え可能な形で保持される前提） |
| 会員 | 会員IDを提示し特典値引きを受ける。保持する会員情報は氏名・性別・年齢のみ（電話番号・住所は取得しない） |
| 一般客 | 会員登録なしで購入する |

### 1.2 商品区分

- 個包装商品：商品本体にバーコードが貼付されている
- 対面販売のパン（バーコードなし）：レジ側の商品コード一覧表（バーコード付き早見表）のバーコードをスキャンして登録する
- 手入力：一覧表のバーコードが読み取れない場合の代替手段

### 1.3 業務フロー

1. レジ担当者ログイン（ID・パスワード＋MFA）
2. 会員ID読込（スキャン／手入力／スキップ可）
3. 商品登録（スキャンまたは手入力の繰り返し）
4. 購入リストの数量変更・削除
5. 会員特典値引きの自動適用
6. 購入確定（税込・税抜合計表示、DB永続化）

---

## 2. 機能要件

### 2.1 画面

- バーコードスキャン用カメラ映像エリア（常時表示）
- スキャン成功時のフィードバック表示
- 商品コード手入力欄
- 購入リスト（名称・数量・単価・小計、選択中行の強調表示）
- 選択商品の数量変更・削除操作
- 値引き適用商品の値引き額表示
- 会員ID表示・入力欄
- ログイン中担当者の表示
- 購入確定操作、税込・税抜合計のポップアップ表示

### 2.2 商品登録（スキャン／手入力）

- カメラでバーコードを読み取り商品コードとして認識できること
- 認識成功時にフィードバックを表示すること
- 連続スキャンに対応すること
- スキャンした商品コードが購入リストに既存の場合は数量を+1し、新規行は追加しないこと
- 未登録の商品コードの場合は新規行として追加すること
- 手入力の場合も同一の挙動とすること

### 2.3 購入リストの操作

- 購入リストから1商品のみ選択できること（複数同時選択は不可）
- 選択中の行は他と区別して表示すること
- 選択商品を削除できること
- 選択商品の数量を1〜99個の範囲で変更でき、変更が小計・合計に反映されること

### 2.4 会員特典の値引き

- 会員限定・期間限定の値引き（割合値引き・金額値引きの両方に対応）を適用できること
- 値引き対象商品・適用期間・値引き内容はコード変更なしに設定変更できること
- 値引き適用商品は値引き額を購入リストに表示すること
- 値引き判定は会員IDの入力タイミング（商品スキャンの前後どちらでも）に依存せず、購入確定前に商品と会員の状態を照合して行うこと
- 会員IDが未入力のまま購入確定した場合は、値引きなしの正常取引として扱うこと
- 入力された会員IDに該当する会員が存在しない場合は、エラーを表示し再入力を促すこと
- 同一商品に複数の有効な値引きが該当する場合は、値引き額が大きい方を適用すること

### 2.5 単価変更時の履歴保持

- 確定済み取引の単価は、その後の商品マスタの単価変更によって改変されないこと

### 2.6 ログイン

- 担当者ID・パスワード・MFA（メールへのワンタイムコード送付）による認証を行うこと
- 誤った認証情報の場合はログインさせずエラーを表示すること
- ログインした担当者情報を取引記録に紐づけること

### 2.7 消費税

- 購入確定時に税込・税抜の両方の合計金額を表示すること
- 消費税率はコード変更なしに設定変更できること
- 税込・税抜合計金額の算出において、1円未満の端数は切り捨てとすること

---

## 3. 非機能要件

### 3.1 セキュリティ

- 認証：ID・パスワード＋MFA（メールワンタイムコード）の二要素とすること
- パスワード：最低15文字以上とすること
- ログイン試行制限：パスワード認証の10回連続失敗で30分間ロックアウトすること（MFAコードの誤入力はこのカウントに含めない）
- パスワードはハッシュ化してDBに保存すること
- 会員の電話番号・住所は取得・保持・表示しないこと
- 通信はHTTPS化すること
- ログインセッションは適切に管理し、第三者による乗っ取りを防ぐこと

### 3.2 運用

- 開店〜閉店の間、応答速度が一定であること（朝の混雑時も遅延しないこと）
- バックエンドはDB接続を維持した状態で稼働すること（リクエストごとのコールドスタート構成を避けること）
- 購入確定・値引き適用・単価変更履歴のデータは永続化され、失われないこと
- 通信断・エラー発生時に、取引が二重確定または未確定のまま確定扱いにならないこと
- 取引は担当者・日時・商品・数量・金額・値引き有無を後から追跡できること
- DBバックアップ等の保守は営業時間外に行うこと
